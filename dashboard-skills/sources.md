# Query languages and discovery
metrics: PromQL / VictoriaMetrics MetricsQL range queries. Discover metric names and labels first, then verify expressions. Counters use rate/increase with an explicit interval; gauges use current/reduced samples. LabelField names a metric label. Query results are series, not single values. Use server-side aggregation when needed.
logs: native VictoriaLogs LogsQL filter followed by | pipes. Discover field names/values. Use fields, stats, sort and limit using native syntax. Numerical visualizations need a named numeric output field, set valueField to that name. Logs widget should query log records, not aggregate statistics. The query API returns at most 100 rows; count queries must aggregate on the source before this cap. Preserve server pipe order.
traces: VictoriaTraces Jaeger URL search parameters: service=URL_ENCODED_NAME&operation=...&tags=URL_ENCODED_JSON&minDuration=...&maxDuration=... . Discover services and operations. Do not generate TraceQL or SQL. Traces expose duration_ms, spans, traceID, service in dashboard adapters. Sample-based summaries represent returned traces, not all traffic.
All calls are read-only and use the selected time range. Existing MCP limits apply. Avoid repeated broad scans; cap discovery to relevant names, labels and small samples.

Configured sources arrive as `available_sources: [{id,kind,name,url}, ...]`. There may be multiple sources for each kind. Every widget must carry both `source` (language kind) and `sourceId` (configured instance ID). Tool names use that instance ID as prefix. Discover each selected ID independently and never silently switch source/tenant. Do not invent or expose credentials.

## Variable option discovery

Dashboard helpers (`label_values(...)`, `metrics()`, `field_values(...)`, `services()`, `operations(...)`) configure native UI selectors; they are not expressions to execute with a query tool. Follow the actual supplied MCP schemas: metric name/label/series tools, log field/value tools, and trace service/operation tools. Tool names and arguments may differ from UI helpers. Preserve chained option expressions as templates in final definitions; use registered bindings to verify concrete samples.
